# nexus-backend-standards

## Async everywhere

Every route, every DB call, every AI call is `async`/`await`. Don't introduce a blocking call
(sync `requests`, sync SQLAlchemy) on a request path — it stalls the whole event loop, not just
that request. If a library only offers a sync client, run it in a thread
(`anyio.to_thread.run_sync` or `fastapi.concurrency.run_in_threadpool`), don't call it directly.

## AI calls go through `app.ai`, never around it

`from app.ai import get_client, embed_texts` — always. Never instantiate `AnthropicVertex` or
a Vertex embeddings client directly in a route or service; the adapter is the single place that
knows about GCP project/region/auth, and it fails with a clear `VertexNotConfigured` error
instead of a raw SDK traceback when unconfigured. A new AI capability (a new prompt, a new
extraction shape) is new *logic* on top of `get_client()`/`embed_texts()`, not a reason to
reach for the SDK directly.

## The API contract is `client/src/types.ts`

Pydantic schemas in `backend/app/schemas/` mirror the matching frontend type field-for-field.
If you're adding or changing a response shape, check what the frontend already expects first —
changing a shape without updating both sides is exactly the kind of break `nexus-plan`'s impact
analysis exists to catch before it happens.

## Models, migrations, schemas — every change together

A new/changed SQLAlchemy model ([backend/app/models/](backend/app/models/)) always ships with
an Alembic migration (`poetry run alembic revision --autogenerate -m "..."`) in the same change
— never a model edit with no migration, and never a hand-written migration when autogenerate
would have caught it. Review the autogenerated migration before applying it; autogenerate
misses some changes (column type nuances, some constraints).

## Errors

Raise `fastapi.HTTPException` with a specific status code and an actionable `detail` message —
matching the product's own "problem + cause + fix" error convention (ui_ux_design.md §7), not
a bare 500. Never let a raw exception (a DB driver error, an SDK error) reach the client
unhandled; catch it at the service boundary and translate it.

## Tests

`pytest-asyncio` + `httpx.ASGITransport` against `app.main.app`, following
[tests/test_health.py](backend/tests/test_health.py) / [tests/test_ai_adapter.py](backend/tests/test_ai_adapter.py).
Cover the success path AND the specific failure modes the plan calls out for that feature (e.g.
§5's hallucination guard, §6's "silent miss is worse than a false alarm" for validation) — not
just a generic happy path.

## Before calling a backend change done

1. `cd backend && poetry run pytest && poetry run ruff check .` — both clean.
2. If a model changed: migration exists and was reviewed.
3. If a route/schema changed: cross-check `client/src/types.ts` for drift.
4. Run `nexus-verify` before considering the work finished.
